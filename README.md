# Contribution Chain

مهمة ورشة البلوك تشين (Tuwaiq Club | UQU)

## الفكرة

أي أحد سوّى مشروع جماعي في الجامعة يعرف المشكلة هذي: فيه عضو ما يشتغل ويطلع بنفس درجتك، أو أحد ياخذ شغلك وينسبه لنفسه، والدكتور ما يدري مين سوّى إيش.
حتى لو استخدمنا Google Docs، صاحب الملف يقدر يعدل أو يحذف براحته.

فقلت ليش ما يكون فيه سجل كل عضو يسجل فيه الجزء اللي سلمه، ومحد يقدر يغير فيه بعدين؟ وهنا يجي دور البلوك تشين.

## هل نحتاج بلوك تشين؟

طبقت الأسئلة اللي في الورشة:
- أكثر من طرف؟ ايه، أعضاء القروب والدكتور
- الأطراف ما يثقون ببعض؟ ايه، هذي أصلًا المشكلة
- نحتاج سجل ما يتعدل؟ ايه
- نبي نستغني عن وسيط واحد؟ ايه، ما نبي السجل بيد شخص واحد

كلها ايه، فالبلوك تشين مناسب.

## نموذج المهمة

| الحقل | الإجابة |
|---|---|
| المشكلة | صعوبة إثبات مين سوّى إيش في المشاريع الجماعية |
| الأطراف | أعضاء القروب + الدكتور |
| ما يُسجَّل | اسم العضو، المهمة، الوقت، وهاش الملف (مو الملف نفسه) |
| نوع الشبكة | خاصة، يديرها القسم أو المقرر |
| الكود | بايثون، كل مساهمة بلوك مربوط بهاش اللي قبله + تحقق من السلسلة + كشف التلاعب |
| القيمة | الدرجات تكون أعدل وكل واحد عنده دليل على شغله |

## الكود

- كلاس `Block` فيه البيانات والهاش حقه
- كل بلوك فيه `previous_hash` يربطه باللي قبله
- `is_valid()` تمر على السلسلة كلها وتتأكد ما فيه شي تغير
- جربت التلاعب: فيصل يغير اسم صاحب السلايدات لاسمه، والبرنامج يكشفه. وحتى لو أعاد حساب الهاش، ينكشف لأن البلوك اللي بعده ما عاد مربوط فيه

وضفت `verify_file()` عشان الدكتور يتأكد إن الملف اللي وصله هو نفسه اللي انسجل.

## التشغيل

```
python contribution_chain.py
```

ما يحتاج أي مكتبات، بايثون بس.

الناتج:
```
OK  -> chain is valid
Contributions per member: {'Turki': 2, 'Sara': 1, 'Faisal': 1}
Slides file matches record? True

=== Tamper attempt 1: Faisal changes block 2 to his name ===
TAMPERING DETECTED -> block 2 was modified (its hash doesn't match its data)

=== Tamper attempt 2: he also recalculates block 2's hash ===
TAMPERING DETECTED -> block 3 is no longer linked to block 2
```

ملاحظة: الهاشات تتغير كل مرة تشغله لأن الوقت داخل فيها.
